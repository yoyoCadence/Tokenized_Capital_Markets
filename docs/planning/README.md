## 先讀這三個結論

1. 現在可以展示研究引擎，但研究資料庫仍是空的；26 項測試通過不能證明實盤可用，更不能證明有超額報酬。
2. 優先建立「當時已知的證據 → 實際持有人經濟收益 → 市價要求 → 可反駁判斷 → 決策紀錄 → 淨績效」的完整閉環。
3. 下一次實作先做 **WP-01：研究資料隔離與嚴格輸入驗證**。接著補歷史可知時間、經濟口徑、混合頻率與快照重播，才發布第一份可供決策的真實研究包。

## 如何使用

- 使用者：先看總體計畫的階段表，再看投資優勢文件的「預先登錄」與「停止條件」。
- 開發 Agent：先讀根目錄 [AGENTS.md](../../AGENTS.md)，再讀現況稽核、第一工作包與 backlog。規劃中的 API、欄位、命令均不是現有功能。
- 研究 Agent：先看來源查核筆記與資料規格。筆記中的網頁不等於已入庫的 OBSERVED。
- 每次實作只推進一個可驗收的工作包；完成後更新任務狀態、測試證據、changelog 與版本，不可只勾選功能名稱。

## 規劃的地位

- Canonical Principles 持續有效；本目錄不能覆蓋現行 spec 或假裝遷移已完成。
- 所有工時、門檻、頻率、績效目標與優先級是 **ANALYST-DEFINED ASSUMPTION**。它們是專案決策，不是市場事實；修改須記理由。
- Fixture 是四種 classification 以外的**資料品質旗標**，不是第五種分類。
- 「能賺錢」暫以**改善自有資金的投資決策與成本後成果**為主目標；付費研究產品是後期可選路線，需另外驗證客戶付費意願。
- 本計畫不承諾收益。若證據顯示沒有優勢，保留現金、停止某個模型、降低研究投入，都是合格產出。
