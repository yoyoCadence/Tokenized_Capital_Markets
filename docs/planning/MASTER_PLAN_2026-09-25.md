## 1. 最終目標與成功定義

### 1.1 Principle：軟體、研究與投資成果分開驗收

「能用」表示使用者可以用可信且可重播的資料，回答現在的價格要求什麼、哪些假設最脆弱、什麼證據會改變判斷。

「能賺錢」表示某種事先定義的決策方法，在可交易條件下，扣除費用、滑價、融資、匯率與適用稅負後，有可觀察的經濟價值。絕對獲利、超額報酬與風險控制要分開報告。一次上漲、勝率提高、好看的回測，都不能單獨證明持續優勢。

本專案首先服務一位研究者／投資者；先解決三個核心標的與其依賴節點。暫不建立交易所、基金管理平台或多租戶 SaaS。

### 1.2 四層成功指標

| 層次 | 可驗收產物 | 初始目標／限制 |
| --- | --- | --- |
| 資料可靠 | 每個決策輸入可追溯且在當時可知 | 決策關鍵欄位 100% 有來源／假設／未知理由；fixture 進研究發布為硬錯誤 |
| 研究可用 | 研究包、反向估值、改變原因、缺口清單 | 同一快照可重播；3 分鐘內找到重大改變，30 分鐘內完成每週檢視，均待使用測試 |
| 決策品質 | 事前預測、反證、成本、持倉理由 | 每次模擬決策都有時間戳與替代方案；不以事後解釋取代原判斷 |
| 經濟成果 | 淨 P&L、適當基準、風險、資本占用、研究成本 | 報告全樣本、失敗與未交易案例；樣本不足時明示無法判定優勢 |

數值目標均為 analyst-defined；先收集實際使用與成本資料，再版本化調整。資料完整率的分母是預先登錄的必要欄位，不能事後刪除難取得欄位來改善分數。

### 1.3 目前位置

MVP 能計算、顯示血緣、跑 sensitivity、thesis rules 與快照比較。它尚無真實研究 observation，也沒有投資成果驗證。現有架構可延伸，重要邊界仍需加固；細節見 [現況稽核](CURRENT_STATE_AUDIT.md)。

## 2. Logic：投資價值來自哪些環節

### 2.1 必須同時成立的鏈條

1. 找到可靠、具有正確時間與口徑的資料。
2. 辨認業務成長是否透過具體機制流入股東／token holder。
3. 由可執行的當前價格反推市場要求。
4. 提出市場可能低估或高估哪一段 economics 的**待驗證假說**。
5. 說明差異如何、何時可能被實現；承認它可能已被價格反映。
6. 計入交易可行性、相關風險與資金占用。
7. 用事前封存的決策與後續結果，檢查是否真的有價值。

任何一段缺失，都可以產生研究任務，不能自動產生交易訊號。

### 2.2 優先研究的 edge hypotheses

| 假說 | 系統可能改善的地方 | 需要的證據 | 否證方式 |
| --- | --- | --- | --- |
| H-UNI：市場過度注意 gross burn，忽略分配與供給 | 重建已實現淨經濟收益、分配、流通供給 | 合約、實際 burn、treasury/vesting、價量時間戳 | 分配調整後沒有增加預測或決策品質，或優勢被成本吃掉 |
| H-SECZ：AUM 敘事與收入／FCF 脫鉤 | 客戶、收入組成、毛利、現金流與股本橋接 | 申報、收入附註、資本結構、交易量定義 | 轉換效率與未來現金流沒有穩定關係，或價格早已反映 |
| H-XLM：網路採用被誤當成 XLM 持有人收益 | 追蹤不可重複計數的增量 native demand | reserve、liquidity、collateral、sponsorship 與供給 | 找不到可識別機制；則不輸出 token fair value |
| H-EVENT：公告、部署與經濟收益的時間差可被追蹤 | 有狀態的事件、傳導延遲與達成率 | 公告、部署、交易與收入四種不同證據 | 公告後收益不可辨識，或事件交易無成本後優勢 |
| H-AVOID：避免脆弱投資能改善整體結果 | 先記錄理由，再比較不交易／基準持有 | 含未交易標的的固定候選集合 | 排除規則沒有改善效用，或機會成本高於避免的損失 |

這些是研究設計，不是已發現的 alpha。先做 H-UNI 的機制核對，再比較其他假說的資料成本與可驗證性；不因研究順序而決定買入順序。

| 階段 | 目標 | 核心工作 | 升級證據 |

| P0 / G0 | 建立可信執行邊界 | fixture 隔離、嚴格 YAML、歷史可知時間、頻率、scope、快照重播、寫入復原 | 惡意／錯誤輸入被拒絕，歷史重播一致，無未解 P0 |
| P1 / G1 | 發布第一份真實研究包 | 來源存證、entity/security master、價量與資本結構、UNI／SECZ／XLM 最小資料 | critical fields 足夠支援限定問題；缺值保留；兩版真實快照可比較 |
| P2 / G2 | 日常研究可用 | 三資產模型 v2、事件流程、資料品質、底層 TAM、決策研究包 | 使用者能回答一個真實決策問題；獨立手算與來源對帳通過 |
| P3 / G3 | 驗證研究是否改善決策 | 預先登錄、預測日誌、成本模型、模擬組合、基準、樣本外分析 | 操作驗收通過；alpha 結論另依樣本／區間，不因通過功能驗收而成立 |

| P5 / G5 | 選擇性擴大 | 新資產、監控自動化、研究產品、規模擴張 | 成本後證據支持，資料授權與操作能力足夠，重新設定風險預算 |

### G0：正確性是進入條件

- RESEARCH 的 observation、event、source、assumption、scenario、graph 證據及衍生 lineage 都不得含 fixture。
- 決策查詢明確使用 economic period、knowledge cutoff、valuation timestamp，晚到／重述資料不能穿越歷史。
- 新增不相關資產的每日報價不改變另一資產季度規則的樣本選取。
- REALIZED、RUN_RATE、MODELED_HORIZON、REVERSE_REQUIREMENT 分別顯示；情境值不能觸發只適用歷史的規則。
- 同一輸入、公式、規則與 runtime 的重播結果相同；損壞快照明確拒絕。
- read-only UI/API 不落盤；發布遇到中斷可恢復；重複事件不重複入帳。
- G0 安全驗收不可用盈利回測補償。

### G1：第一包真資料可以局部完整

首包目標是「回答限定問題」，不是把所有格子填滿。三資產逐一發布 readiness：

- UNI：至少能核對一段已完成期間的 fees、burn、distribution 與市場分母。
- SECZ：確認實體與可交易工具、最近正式財務期間、收入總額及資本結構；未披露六分項保留未知。
- XLM：確認可觀察採用資料、至少一種 native-demand 機制與重複計數邊界；若不能估值，輸出原因與需要的證據。
- 每包說明 coverage、stale/conflict、reconciliation residual、mechanism confidence；不得以總分掩蓋一個致命缺口。
- 若一個標的未達門檻，其他達標標的可以發布；未達標者保留研究節點，不能借用它們的通過狀態。

### G2：完成一次真實工作流

從新資料進來，到比較報告、反向要求、情境分析、反證、決策備忘錄。需要顯示「現在能回答什麼」「還不能回答什麼」「哪個輸入最值得研究」。不要求一定得到買入結論。

### G3：影子操作與優勢判定分開

建議先觀察 **8–12 週**的資料更新、模擬記錄與成本偏差，作為操作試運轉的初始時間假設。這不等於足夠驗證 1–3 年投資 thesis。年度問題必須等待成熟結果，短期代理指標不得冒充長期報酬。

無法取得足夠獨立觀察時，標為「尚未證實」，並繼續有限研究或停止該假說。小樣本下不能因信賴區間不顯著便證明「沒有優勢」，也不能因平均值為正便宣稱「有優勢」。

### G4：投入資金需要新的具體政策

本次沒有授權自動交易。未來有限人工試行前，需使用者提供資本規模、基準幣別、投資期限、可接受損失、流動性需求、可用市場與帳戶限制；接受可能無優勢的試驗性質。不能由 thesis state 自動映射成下單。

## 4. 建議實作順序

### 4.1 第一個可獨立驗收的工作包

**WP-01：研究／fixture 邊界與嚴格 YAML 載入。**

現在已有可重現的錯誤案例，修正範圍小、測試明確，也是後續真實資料的共同前提。詳細任務見 [第一個工作包](FIRST_IMPLEMENTATION_PACKAGE.md)。

### 4.2 後續順序

1. P0 輸入隔離與錯誤診斷。
2. 時間／scope 契約，版本遷移與混合頻率規則。
3. 快照完整重播、完整性與發布事務。
4. 建立一份人工核對的 UNI 證據包，同步驗證 source workflow；來源查找可提早做，未通過 G0 不作決策發布。
5. SECZ 財報與股本／EV，再做 XLM 採用和需求機制。
6. 真實／模型／reverse 面板分離、研究缺口與變更解釋。
7. 事前預測與決策紀錄、成本後模擬、獨立基準。
8. 在資料與樣本條件允許時建立預期報酬／永久損失模型。
9. 只有後續明確授權，才進行人工小額實證與自動化。

「先做一份資料包」的意義是把來源→對帳→重播走完整次；不一次接二十個資料商，也不先換 UI 框架。

## 5. 產品工作流與頁面責任

### 5.1 每日：只處理會改變決策的事情

首頁是研究工作佇列：

- 新來源／重述／事件，與受影響資產。
- 過期的價格、缺失期間、衝突證據。
- 需要重估的經濟收益與市場要求。
- 已過期的預測、未結案的反證與執行偏差。

價格變化和證據變化分開。沒有重大變更時，系統應能說明「截至何時、哪些來源未變」，不能每天生成新的敘事當作進展。

### 5.2 每週：生成可審閱的決策研究包

1. 資產／工具身分、資料 cutoff、模型版本與 eligibility。
2. 目前價格、估值、可執行條件與交易成本區間。
3. 已實現 economics、run rate、未來 scenarios 的獨立表格。
4. 市場要求的 economics、差距、最重要敏感參數。
5. 支持與反對證據、替代解釋、事件狀態與時間。
6. 假說、預測機率／區間、解析條件、哪項證據會推翻。
7. 候選動作：繼續研究／不交易／模擬提案；不讓規則引擎代替使用者決策。
8. 與前次比較：source、record、assumption、scenario、formula、rule、price 各自變化；多因素交互作用另列。

### 5.3 每季：關閉預測與檢查模型

更新財務與治理紀錄、結算到期預測、檢查信心水準與實際命中、比較淨績效／風險。修改規則先解釋原因，再開新版本重新驗證；保留原版本績效。

### 5.4 Data Inspector 的下一版

新增 economic period、published/first-seen、knowledge cutoff、native unit、FX 來源、scope/horizon、原文定位、原檔 digest、全部 supporting/conflicting records、quality issues、採用／拒用理由。每個 missing 值附 reason code；不顯示無依據的「0」。

### 5.5 Graph 的用途

顯示一般依賴與經濟傳導兩張可切換的圖；邊上有 status、source、延遲假設、可反駁條件、實際 exposure。圖不是 alpha 排名，節點較多也不代表研究較好。

## 6. 架構決策

保留 Python 計算核心、human-readable YAML、離線可讀的快照、輕量本地 UI。短期不引入雲端付費資料庫或把 LLM SDK 放進模型。

| 層 | 未來責任 | 邊界 |
| --- | --- | --- |
| evidence archive | 保存可重現原始資料與 hash／定位 | 公開 repo 不放受限授權全文、帳號、持倉個資 |
| canonical ledger | 只追加版本、雙時間查詢、來源衝突 | YAML 為可審閱 canonical；私有資料可另一路徑 |
| compute | 單位／時間／scope 檢查、模型 DAG | deterministic，外部搜尋不能在公式求值中發生 |
| decision research | 反向要求、scenarios、預測與反證 | 不自動產生交易承諾 |
| evaluation | 基準、成本、校準、模擬紀錄 | 凍結實驗與測試資料切分 |
| presentation | 工作佇列、研究包、血緣、差異 | 不硬編金融資料與 canonical 規則 |
| optional adapters | SEC、治理、鏈上、報價、AI extraction | provider 可替換；失敗不能沿用舊值而不標示 |

當 YAML 的搜尋／寫入成為實測瓶頸，可用 SQLite 作可重建索引或發布 journal。除非有完整遷移 ADR，不另立一個與 YAML 競爭的財務真相。採購或技術升級由瓶頸決定。

## 7. 資源、時程與經濟合理性

以下是一位主要開發者搭配具領域判斷研究者的**規劃估計**，不是交付承諾。詳細任務以 backlog 的 effort_points 表示相對複雜度，不能直接相加成日曆日期。

| 階段 | 主動工作量初估 | 外部等待／風險 |
| --- | --- | --- |
| P0 | 8–15 工程日 | 資料契約與遷移設計可能擴大 |
| P1 | 8–15 研究日＋4–8 工程日 | 原始披露不足、來源可達性、合約辨識 |
| P2 | 10–18 工程／研究日 | 模型口徑與對帳是主要變因 |
| P3 | 8–15 工程／研究日＋至少 8–12 週操作觀察 | 投資結果成熟可能需數季或數年 |
| P4 | 3–5 日設定＋持續記錄 | 取決於使用者政策與實際授權 |
| P5 | 不估總工期 | 需重新立項，不能默認實作 |

前兩次迭代每次 3–5 工作日，結束時只根據已完成工作與缺口重估。Agent 可降低編碼時間，不能縮短財報發布、治理成熟或投資結果實現時間。

### 7.1 專案本身也要接受經濟檢驗

假設可運用資本 C、成本後超額報酬假設 a、年度資料／工具成本 D、研究時間 H 與每小時機會成本 W：

~~~text
研究專案年度經濟增益假說 = C × a − D − H × W
~~~

這只是事前規劃的簡化情境，不是 alpha 估計；a 可能為負，尾端損失另評估。

**純假設例子**：C = US$100,000、a = 3%、D = US$600、H = 100 小時、W = US$30，則結果為 −US$600。代表即使假設有 3% 額外報酬，研究成本仍可能不划算。數字沒有任何市場來源，也不是對使用者本金或收益的預測。

每月記錄實際研究時間、工具費、資料費與節省的時間；先用免費官方資料，只有具體研究瓶頸和授權可行時才買資料。

## 8. 風險與停止條件

| 風險 | 早期訊號 | 行動 |
| --- | --- | --- |
| 沒有真實資料 | 面板長期依賴 assumptions | 降低功能範圍，先手動做一份可對帳研究包 |
| 沒有 value capture | 採用上升但持有人機制不明 | 不輸出 fair value；保留 dependency node |
| 沒有可重現優勢 | 淨結果被基準、成本或樣本誤差解釋 | 停止該訊號的資本擴張，保留研究用途 |
| 過度擬合 | 規則一直因最近結果而改 | 凍結版本，記試驗次數，另用未看過資料 |
| 模型錯誤造成假訊號 | 重述、時點、範圍不符 | 暫停受影響結果發布與新模擬決策，修復後重播 |
| 題材共振 | UNI／SECZ／XLM 同時受風險偏好影響 | 按共同驅動與壓力情境看暴露，不當作三個獨立押注 |
| 工程吞噬研究價值 | 新功能增加，決策問題無改善 | 設功能 WIP 上限；下一功能需證明它回答哪個問題 |
| 專有資料外洩 | 公開 repo 出現帳戶／受限全文 | 將原始私有資料保留於指定私有儲存；公開僅 schema／fixture／可公開摘要 |

停止某個交易假說，不等於刪除歷史紀錄。保留反例、失败與否證，比保留漂亮的單一路徑更重要。

## 9. 可選商業化路線

只有自用研究穩定後，才考慮對外提供「有來源與版本的研究工作台／研究包」。先驗證使用者願意為哪個工作節省時間、願付多少與是否續用；先訪談與原型，不先做 billing／多租戶。

商業化要另算客單價、服務時間、資料轉授權成本、留存與毛利。不得用回測報酬宣稱產品保證收益。資料授權、投資研究服務的適用規範與地區限制需在那個階段重新向一級資料與專業人士確認，本計畫不作法律判定。

這條路線屬 P5，當前不實施，也不把服務營收和個人投資報酬混成同一成功指標。

## 10. 還需要使用者回答的政策問題

現在可繼續 P0–P2，不需等待這些答案。進入模擬績效基準／真實資本前，則必須逐步確認：

1. 主要目標：絕對報酬、相對哪個基準的超額報酬，還是避免永久損失？
2. 可研究資本規模、基準幣別、現金需要與可接受回撤／永久損失。
3. 時間範圍、持有與再平衡頻率、可投入研究時間。
4. 可使用的交易工具、帳戶、市場、稅務與地區限制。
5. 哪些資料可以公開到本 repo，哪些必須私有？

更高一層的決策問題是：**哪一個目前會做錯、做太慢或無法驗證的資本配置決策，值得這個系統優先改善？**
